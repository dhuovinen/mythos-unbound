# Battle diagnostics implementation

- Objective: complete factual battle capture with a readable viewer and self-contained evidence exports for separate analysis.
- Implemented: optional combat observer on the same tick path; exact per-tick report recording; attack calculations and full pre-attack fields; target changes and deaths; initial state and one-second checkpoints; summon attempts, availability, free scripted waves, paid deployments, AI decisions, settings and fast-forward mode transitions.
- UI: always-available Battle log button, gear-menu entry and completed-report entry. Frozen snapshot viewer with event filters, search, pagination, numerical attack detail and exact JSON. Full Markdown and JSON exports include game rules, roster, graph, engine source and external review prompt. No diagnostic analysis or model calls.
- Verification: 156 tests pass, including observed/unobserved world equality, ordinary hits, defensive aura maths, suppression, cross-pantheon attacks with allied auras, armour penetration, base IDs, overkill, deaths, availability and lossless exports beyond 120 rows.
- Browser verification: manual accepted/refused summons and hand/cost evidence, complete instant resolution, completed report entry, attack filters and details, both packet formats and a 20,000-character export preview. A generated 250 KB live JSON packet was read back from the UI and parsed successfully. A completed Markdown packet contained 1,052 events / 403 attacks / 47 deployments and included the external prompt. The final attack viewer includes range and exact ally instance pools, with no console warnings/errors. Screenshot: `/tmp/battle-diagnostics.jpg`.
- Download verification limitation: the in-app browser's download event and file-link automation timed out. The download link remains available, plus Copy complete export; denied clipboard access selects the complete text for manual copying. Copy action reports success in the browser. Downloads and copying include all events, while the visible preview alone is shortened to keep large battles responsive.
- Final checks: all 156 tests pass, production build/typecheck clean, registry validation passed, own diff reviewed and whitespace checks clean. Runbook in NOTES.md includes entry points and external review workflow. Ready for evaluation; recording is memory-only and a page reload starts a new log.
